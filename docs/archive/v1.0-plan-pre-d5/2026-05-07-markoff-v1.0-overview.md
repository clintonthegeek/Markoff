# Markoff v1.0 — Implementation Plan Overview

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement each part task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. **Execute parts in order.** Each part ends with green tests; the next part assumes the previous part has landed.

**Goal:** Ship Markoff v1.0 — clean-break public API, finished QML-based live widget (perf + link handling), Reading-as-readonly, source-widget alignment, library reorganisation, frozen Corbomite migration guide, merge to main, tag `v1.0.0`.

**Architecture:** Five libraries (`markoff-parser`, `markoff-core`, `markoff-live`, `markoff-source`) plus the deleted `markoff-view-qml`. Consumer-facing primitives in `Markoff::` namespace (`MarkdownView`, `MarkoffDocument`, `CursorPos`, `Theme`, `EditorContext`, `ActionId`, `BlockKindNames`); CRDT internals in `Markoff::Core::`. Live widget is a `QWidget` hosting a `QQuickWidget`; the QML scene drives the per-block CRDT model with **targeted updates** instead of full-document walks. Reading mode is `Live::Editor` with `setReadOnly(true)`.

**Tech Stack:** C++20, Qt6.8+ (Core, Gui, Widgets, Qml, Quick, QuickWidgets, Test), CMake 3.19+, KF6::SyntaxHighlighting, QTest, the existing tree-sitter parser, the QML `DelegateChooser` pattern, `rapidyaml` (vendored).

**Spec:** `docs/specs/2026-05-07-markoff-v1.0-design.md` (read this first; the plan executes the spec).

## 3. Definition of done (mirrors spec §8)

Pass criteria for v1.0:

- All work units across Parts 1–5 merged to `foundation-exploration`, each with green tests at merge time.
- The 103 existing tests (post-D4 baseline) remain green throughout.
- New tests cover:
  - QWidget facade lifecycle (construct, attach document, destroy).
  - The `MarkdownView` base contract — one test per concrete subclass (`Live::Editor`, `Source::Editor`) exercising every base method.
  - Link emission (`linkClicked`, `linkHovered`) on synthesized mouse events.
  - `setReadOnly(true)` behaviour: editing keystrokes ignored, cursor still navigable, `hasEditing()` returns `false`.
  - `documentChanged()` semantics — emitted on edit, not on read.
  - The new `Markoff::Parser` namespace (compile-only test verifying include paths and namespace).
- Perf benchmark in `tests/perf/` passes on the CI reference machine: 500-line document → window visible ≤500 ms, peak RSS ≤300 MB, idle CPU between keystrokes ≤2%.
- Test app `markoff-testapp` exercises Live edit, Live read-only, and Source — three modes on one document, mode-switching state preserved.
- Migration guide at `docs/handoff/2026-05-07-markoff-v1.0-corbomite-migration.md` reviewed and frozen.
- `v1.0.0` tag pushed to `main`.

## 4. Cross-cutting conventions

These conventions apply across every part. Each part's "Read first" section refers back here rather than restating.

**Build cap:** `cmake --build … -j 8` and `ctest … -j 8`. Never bare `-j` or higher.

**SPDX header:** every new C++/QML file begins with `// SPDX-License-Identifier: GPL-3.0-or-later`.

**Translation:** every user-visible string uses `tr()`. Test apps and headless tools may use plain literals.

**Icons:** `QIcon::fromTheme(...)` for icons. Test apps may use Qt-bundled SVGs as fallback.

**Test files:** new tests go under `tests/v10/` with the prefix `tst_v10_<phase>_<topic>.cpp`. The CMake `tests/CMakeLists.txt` registers them via `markoff_add_test(...)`.

**Commit messages:** use the local convention from the d-arc plans: `<area>: <subject>` (lower case, terse), with a short body when the change has non-obvious motivation. Examples:
- `markoff-core: define MarkdownView base class`
- `live: replace onD2Changed full-walk with targeted handler (Part 3 Phase 2)`
- `migration: draft v1.0 corbomite handoff`

**Branch:** all work lands on `exploration/new-foundation`. Do not create per-phase branches; commit in sequence on the same branch. The merge to `main` happens once in Part 5.

**Test green at every commit:** end every task with a successful `ctest -j 8 --output-on-failure`. Do not commit a red tree, even mid-phase. If a phase requires a partial state (e.g. a header exists but isn't consumed yet), structure it so the partial state still compiles and passes the existing test set.

**Memory of past pain (reminders for the executing agent):**
- Never let an inspection subagent run `git checkout <sha>`; in a worktree it detaches HEAD silently and the next controller commit lands on a dangling ref. Use `git show <sha>:<path>` for read-only inspection.
- Don't bare `-j` on builds (CPU saturation).
- This branch (`exploration/new-foundation`) is the active branch. The master tree is *outgoing* — read foundation-exploration paths, not master paths, when comparing.

## 5. What's deferred to v1.1+ (so the executor doesn't try to add it)

Per spec §2.2 and §9, these are explicitly **out of scope** for v1.0:

- Inline styling rendering (bold / italic / inline code / strikethrough rendered as styled text).
- Delineator hiding (cursor-aware suppression of `**`, `` ` ``, etc.).
- Tables (pipe tables remain rendered as paragraphs of literal source text).
- D5 / collab activation. Single-user local only.
- The C1 DI seam: `LinkResolver`, `Vault::MetadataCache`, `Vault::MetadataParser`, `EmbedRegistry`, `CodeBlockRegistry`, `MermaidRenderer` — none return.
- Plugin extension API (custom block kinds, code-block language renderers, embed renderers, decoration providers, toolbar/context-menu extensions). v1.0 ships zero extension API but is designed not to foreclose them — see spec §9.
- A dedicated reading widget. `Live::Editor` with `setReadOnly(true)` covers all three v0.x reading-view sites.

If a phase tempts you to "while I'm here, I'll add X" where X is in this list — stop. Land the v1.0 phase as specified; the v1.1+ work has its own future plan.
