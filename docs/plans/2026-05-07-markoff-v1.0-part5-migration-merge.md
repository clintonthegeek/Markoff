# Markoff v1.0 — Migration Guide for Corbomite

**Audience:** Corbomite engineers.
**Frozen against:** Markoff v1.0 API at git commit tagged `v1.0-api-freeze` (see header of this commit on `main` once merged).
**Spec source of truth:** `docs/specs/2026-05-07-markoff-v1.0-design.md` (in the Markoff repo).

This guide describes how to adapt Corbomite (currently consuming Markoff at submodule version `v0.9.1`) to Markoff v1.0. v1.0 is a clean break: no backwards-compatibility layer, no shim. The mapping below tells you, file by file, what to change.

## 1. Why a clean break

The foundation-exploration D-arc reshaped Markoff's internals around a per-block CRDT (`MarkoffDocument`). The v0.x API was designed around a different document model and a separate `Reading` widget that no longer exists. Rather than building a translation layer that hides the new shape, Markoff publishes the new shape as its v1.0 API and asks consumers to adapt once. The result is a leaner surface (no DI seam, no abstract registries) and a foundation that supports the v1.1+ extensibility horizon (plugin-defined block kinds, code-block language renderers, embed renderers — see Markoff spec §9).

## 2. What changes — class / signal / method mapping

| Old (v0.9.x) | New (v1.0) | Notes |
|---|---|---|
| `Markoff::Editor` (live) | `Markoff::Live::Editor` | Now lives in `<markoff/live/Editor.h>`. QWidget hosting QQuickWidget. |
| `Markoff::Source::SourceEditor` | `Markoff::Source::Editor` | Class renamed to `Editor` (matches the namespace). Now lives in `<markoff/source/Editor.h>`. QPlainTextEdit-backed (Qutepart removed). |
| `Markoff::Reading::ReadingView` | `Markoff::Live::Editor` with `setReadOnly(true)` | No separate Reading widget. The same `Live::Editor` instance, configured read-only, replaces every `ReadingView` call site. |
| `Markoff::MarkdownView` | `Markoff::MarkdownView` | Same name, in `<markoff/core/MarkdownView.h>`. Concrete (not abstract) QWidget base. |
| `Markoff::MarkoffDocument` | `Markoff::MarkoffDocument` | Same name, in `<markoff/core/MarkoffDocument.h>`. Internal model is per-block CRDT; consumer surface is reshaped (see signal table). |
| `Markoff::MarkdownDelta` | (removed; not exposed) | The v0.x ORC delta object is foundation-internal in v1.0. If Corbomite was using it externally, see §6 below. |
| `Markoff::EditorContext` | `Markoff::EditorContext` | `blockKind` is now `QString` (was an enum). Use `Markoff::BlockKindNames::*` constants for canonical names. |
| `Markoff::ActionId` | `Markoff::ActionId` | Same enum class. Same value set. |
| `Markoff::Theme` | `Markoff::Theme` | Same. |
| `Markoff::MermaidRenderer` (abstract) | (removed) | Mermaid rendering is no longer a Markoff concern. Corbomite already has its own renderer; keep it Corbomite-side. No injection. |
| `Markoff::LinkResolver`         | (removed) | DI seam gone. Markoff emits `linkClicked(QString href, Qt::KeyboardModifiers)`; the host (Corbomite) resolves. |
| `Markoff::EmbedRegistry`        | (removed) | DI seam gone. v1.0 has no embed-renderer integration; deferred to v1.1. |
| `Markoff::CodeBlockRegistry`    | (removed) | Same. |
| `Markoff::Vault::MetadataCache` / `Markoff::Vault::MetadataParser` | (removed) | Same. |

### Signal contract on `Markoff::MarkoffDocument`

| Old | New |
|---|---|
| `void contentsChanged(qsizetype offset, qsizetype removed, qsizetype inserted)` | `void documentChanged()` — no args |
| `void documentReloaded()` | unchanged |
| (none) | `void blocksChanged(QList<Markoff::Core::BlockId> ids)` (additive; advanced) |
| (none) | `void blockInserted(Markoff::Core::BlockId id, int row)` (additive; advanced) |
| (none) | `void blockRemoved(Markoff::Core::BlockId id, int row)` (additive; advanced) |

Corbomite's only consumer of `contentsChanged` was `NoteDocument::onTextChanged` (sets `modified = true` and re-emits `textChanged()`). Migration: connect to `documentChanged()` with a no-arg slot.

### Signal contract on `Markoff::Live::Editor`

| Old (`Markoff::Editor`) | New (`Markoff::Live::Editor`) |
|---|---|
| `linkClicked(QString href)` | `linkClicked(QString href, Qt::KeyboardModifiers modifiers)` |
| `linkHovered(QString href, QPoint globalPos)` | unchanged |
| `textChanged()` | (removed; subscribe to `MarkoffDocument::documentChanged()` instead) |
| `cursorPositionChanged(int line, int column)` | unchanged (declared on `MarkdownView` base) |
| `completionDismissHint()` | (removed for v1.0; reintroduce in v1.1 if needed) |
| `contextChanged()` | `contextChanged(Markoff::EditorContext ctx)` — context now passes a snapshot |
| (none) | `imageSourceRequested(QString relPath, QString token)` (new — see §5) |

## 3. Per-file migration steps for Corbomite

### `src/editor/MarkdownView.cpp`

- Replace `<markoff/source/SourceEditor.h>` with `<markoff/source/Editor.h>`.
- Replace `<markoff/reading/ReadingView.h>` with `<markoff/live/Editor.h>`.
- Replace `<markoff/Editor.h>` with `<markoff/live/Editor.h>`.
- Class names: `Markoff::Source::SourceEditor` → `Markoff::Source::Editor`; `Markoff::Reading::ReadingView` → `Markoff::Live::Editor` (constructed with `setReadOnly(true)`).
- The `MarkdownView` base interface itself is unchanged in capability surface, but the include path is now `<markoff/core/MarkdownView.h>`.

### `src/editor/NoteEditorWidget.cpp`

- Update includes: drop `<markoff/MarkdownDelta.h>`, `<markoff/MermaidRenderer.h>`, `<markoff/EmbedRegistry.h>`. Keep `<markoff/core/MarkoffDocument.h>`, `<markoff/live/Editor.h>`, `<markoff/source/Editor.h>`, `<markoff/core/MarkdownView.h>`.
- Replace `Markoff::Editor` with `Markoff::Live::Editor` everywhere in this file. Construct the same way: `new Markoff::Live::Editor(this)`.
- The Reading-mode leaf at stack index 2 is now also a `Markoff::Live::Editor`, constructed with `setReadOnly(true)`.
- `linkClicked(QString)` slot signature now takes `(QString, Qt::KeyboardModifiers)`. Add a `Qt::KeyboardModifiers` parameter to your slot and route Ctrl-click to a different code path if you want to (e.g. open in new pane).
- Remove all `setMermaidRenderer`, `setResourceProvider`, and DI-seam injection calls. They no longer exist on the new editor classes.
- Where the old code constructed a `Markoff::MarkdownDelta`: that path is gone. Edits should be applied via `MarkoffDocument::loadFromMarkdown` (full reload) or — for advanced incremental writes — `MarkoffDocument::applyFlatEdit(QString)` which lives in `<markoff/core/MarkoffDocument.h>`. If your delta usage was a one-off optimization for partial updates, drop it for v1.0 and reintroduce in v1.1 if benchmarks show a regression.
- `contentsChanged(off, rem, ins)` slot becomes `documentChanged()` — no arguments. Adjust your slot.

### `src/editor/HoverPopover.cpp`

- Replace `<markoff/reading/ReadingView.h>` with `<markoff/live/Editor.h>`.
- Replace `Markoff::Reading::ReadingView` with `Markoff::Live::Editor` constructed with `setReadOnly(true)`.
- Remove `setMermaidRenderer`, `setLinkResolver`, `setMetadataCache`, `setMetadataParser`, `setEmbedRegistry`, `setCodeBlockRegistry` calls — these injectors no longer exist.
- The `linkHovered` signal still works the same way.

### `src/app/MainWindow.cpp`

- The `contextChanged` signal subscription on the live editor now receives a `Markoff::EditorContext` argument (the snapshot, instead of a no-arg notification with a separate `context()` getter). Update the slot to take `Markoff::EditorContext`.
- `EditorContext::blockKind` is now a `QString`, not an enum. Compare with `Markoff::BlockKindNames::Heading` etc. (or inline string literals).
- The toolbar's bold / italic / inline-code in-state probes (`inBold`, `inItalic`, `inInlineCode`, etc. on the old `EditorContext`) **do not exist in v1.0**. The toolbar buttons can still fire `Markoff::Live::Editor::action(Markoff::ActionId::Bold)` to insert markers, but the visual "is the cursor in a bold span" indicator is gone for v1.0 (lights up in v1.1 alongside inline-styling rendering). Decide whether to hide those toolbar checkmarks or just leave them unchecked.

### `src/editor/SourceEditor.h` / `.cpp`

If Corbomite has a thin wrapper around `Markoff::Source::SourceEditor`, rename to wrap `Markoff::Source::Editor` instead. The base capability — `MarkdownView` overrides — is unchanged.

### `libs/core/src/NoteDocument.cpp`

- Replace `<markoff/MarkoffDocument.h>` with `<markoff/core/MarkoffDocument.h>`.
- Adjust the `contentsChanged(off, rem, ins)` connect to `documentChanged()` (no-arg).
- The `Markoff::Origin` enum (passed to `resetContent(text, Origin)`) — verify it still exists at `<markoff/core/MarkoffDocument.h>`. If not, the v1.0 surface uses `loadFromMarkdown(QString)` only; remove the `Origin` argument from your call.

### `libs/core/include/corbomite/markoff_adapters/Adapters.h`

**Delete this file.** The C1 DI seam is gone in v1.0. The wrapped Corbomite types (`Corbomite::LinkResolver`, `Corbomite::MetadataCache`, `Corbomite::MetadataParser`) stay Corbomite-side; nothing wraps them through a Markoff abstraction anymore.

The behaviour these adapters provided (link resolution, metadata cache lookup) now happens in Corbomite's `linkClicked` / `linkHovered` slots and in the host's vault layer directly. There is no Markoff-side coupling.

## 4. Removed features and their replacements

These features in v0.x **are not present in v1.0**. Plan accordingly:

- **Inline styling rendering.** v0.x rendered `**bold**` as styled bold text; v1.0 shows the literal source until v1.1.
- **Delineator hiding.** v0.x hid `**`, `` ` ``, etc. when the cursor left the run; v1.0 always shows them.
- **Tables.** v0.x rendered pipe tables; v1.0 shows raw pipe-text in the live widget.
- **Mermaid rendering.** Markoff no longer integrates this; Corbomite keeps its mmdr-backed renderer entirely Corbomite-side.
- **Embed registry / code-block registry.** Removed. Corbomite's existing registries stay Corbomite-side and no longer wrap a Markoff abstraction.
- **In-span context probes (`EditorContext::inBold`, `inItalic`, etc.).** Removed for v1.0 — the toolbar checkmarks for inline-style state will not light up. Inline-styling is the primary v1.1 feature; these come back with it.

These are visible regressions in Corbomite's editor for the duration v1.0 → v1.1. They are an accepted cost of the clean break.

## 5. Image source resolution (new feature)

Markoff's image rendering for `![alt](path/to/image.png)` and `![[image.png]]` blocks now requests the source from the host asynchronously rather than expecting a resolved file URL. Connect:

```cpp
connect(editor, &Markoff::Live::Editor::imageSourceRequested,
        this, [editor, this](QString relPath, QString token) {
    const QString resolved = m_vault->resolveImagePath(relPath);
    editor->provideImageSource(token, resolved);
});
```

If the host doesn't connect, images don't render. (v1.0 default behaviour: a placeholder rectangle.)

## 6. New advanced surface — targeted block-update signals

These are not required by Corbomite's UI integration but are available if you want to react to document edits per block:

- `MarkoffDocument::blocksChanged(QList<Markoff::Core::BlockId> ids)` — fired when block buffers were edited.
- `MarkoffDocument::blockInserted(Markoff::Core::BlockId id, int row)` — fired on structural insertions.
- `MarkoffDocument::blockRemoved(Markoff::Core::BlockId id, int row)` — fired on structural removals.

These power the live widget's incremental rendering. Don't connect to them unless you actually need the per-block granularity — `documentChanged()` is sufficient for dirty-tracking.
