# E4 — Tables — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `BlockKind::Table` as the first multi-cell internally-editable member of L8 (interactive blocks). Pipe-tables in source render as graphical grids in Live mode; cells are individually focusable; navigation follows Word/Obsidian conventions; cell content supports inline formatting; the alignment row and `|` separators are never visible in Live; no Live-mode edit can produce a non-table from a table.

**Architecture:** One `BlockKind::Table` block per pipe-table; block buffer = exact pipe-table source bytes (passthrough serializer, already registered). New `TableDelegate.qml` parses the buffer into a `ParsedTable` (headers, alignments, body cells, per-cell byte ranges in the buffer); renders an N×M grid of `TextEdit` cells. A new `TableEditBinding` (modeled on `LiveEditBinding`) translates per-cell `contentsChange` events into block-buffer byte-range mutations.

**Tech Stack:** Qt6.8+ (Quick, Quick.Controls, Test), C++20, CMake 3.19+, existing `MarkoffDocument::d2ApplyBufferEdit` + `InlineHighlighter` machinery + `LiveCursorState` chokepoint.

**Spec:** `docs/specs/2026-05-22-e4-tables-design.md`. Read it before starting; cite section numbers in commit messages where relevant.

**Conventions:**
- Build: `cmake --build build-dev --target <target> -j 8` (never bare `-j`).
- Tests: `scripts/run-tests.sh --bin <test_binary>` (defaults to `QT_QPA_PLATFORM=offscreen`).
- SPDX header `// SPDX-License-Identifier: GPL-3.0-or-later` on every new source file.
- `tr()` for user-visible strings.
- TDD: failing test → implementation → green → commit. Frequent commits.
- Falsifiability proofs (per `docs/INVARIANTS.md` invariant 4): for each load-bearing invariant test, the implementation commit must be preceded by a "stub falsifiability proof" commit pair in history — the test fails when the relevant code is stubbed; reverted before the real implementation lands.

**Plan-time resolutions** (defer-from-spec decisions baked here):
- The phase tag is `v0.7.0-e4` on dogfood pass.
- The dogfood request file is `docs/handoff/2026-05-22-e4-dogfood-request.md`.
- Test fixture markdown lives at `libs/markoff-live/tests/fixtures/tables_basic.md` (new) and is loaded by the realistic-input harness for E4 tests.
- `TableEditBinding` is C++ (Q_OBJECT, Q_INVOKABLE), header under `libs/markoff-live/include/markoff/live/TableEditBinding.h`, source under `libs/markoff-live/src/TableEditBinding.cpp`. JS-only would force the buffer-byte arithmetic into QML — unwise for the canonical translator.
- `ParsedTable` derivation lives in JS inside `TableDelegate.qml` for B (cheaper to iterate visually). If profiling shows the parse is hot, the lift-to-C++ task is a successor.
- Slot reuse: cell background = `CodeBlockBackground`; grid lines = `Quote`. If dogfood says they need their own slots, splitting is a follow-up.

## Risks and unknowns

1. **`LiveCursorState`'s `BlockInternalEdit` API surface.** The spec assumes `establishBlockSelected` and `establishBlockInternalEdit` (or equivalent) exist. If they don't, Phase D3 / E1 / E2 must add them. Investigate at the start of Phase D.

2. **Re-entrance under cell `text` binding refresh.** When a buffer edit fires, all cells' `text` bindings re-evaluate. If the active cell's `text` *changes* even though its content didn't (e.g., padding normalized differently), the cell's `onContentsChange` fires synchronously inside our edit, potentially looping. The C2 step 5 guard handles the common case; if a subtle case slips through, document and add an additional guard.

3. **`Qt.callLater` candidates.** Phase B3 step 4 (`takeFocus`) and Phase D2 cross-row Up/Down may need a `Qt.callLater` if cell child creation isn't synchronous with the delegate's `Component.onCompleted`. Try synchronous first; document any deferrals.

4. **Existing test failures.** The current baseline has 2 known failures (`tst_live_render_focus_chokepoint_invariant` undo/redo + `tst_live_render_cursor_typing_invariant` emoji-typing — both pre-date this work). If E4 work surfaces a third, classify per the discipline-log rule, do not bundle with E4.

5. **Cell visual sizing aesthetics.** First-pass column widths are content-driven with a `Layout.minimumWidth` floor. If the dogfood pass says columns look ragged or too narrow, tweak the sizing model in a follow-up commit — that's a styling adjustment, not a re-architecture.
