# Markoff v1.0 — Design

**Status:** draft (spec phase)
**Date:** 2026-05-07
**Audience:** Markoff implementers (and the spec freeze is the source of truth for the Corbomite migration guide)
**Supersedes:** all prior phase / d-arc specs as the *active* roadmap. Historical specs remain in place for archival reference; this document is the single forward-looking plan.

## 1. Mission

Replace the current `master` Markoff (v0.9.x, consumed by Corbomite at submodule version `v0.9.1`) with the foundation-exploration tree as a coherent, named **Markoff v1.0**. Refine the parts of foundation-exploration that are not yet consumer-ready into a deliberate consumer-facing API, finish the live-render widget enough for daily use, and hand off to the Corbomite team a frozen API contract plus a migration guide.

The alignment target is Corbomite, the only consumer. The API is shaped to fit Corbomite's actual call sites: `NoteEditorWidget`, `MarkdownView`, `HoverPopover`, the `MarkdownRenderer::render` plugin verb, `MainWindow` toolbar wiring, and `NoteDocument`.

This is a **clean break.** There is no backwards-compatibility layer. Corbomite adapts.

## 2. Scope

### 2.1 In scope

- Markoff v1.0 public API (Section 4).
- `Markoff::Live::Editor` QWidget facade hosting the QML scene; performance fixed; link handling working (Section 5).
- "Reading view" delivered as `Live::Editor` constructed with `setReadOnly(true)` — no separate widget class.
- `Markoff::Source::Editor` (the new QPlainTextEdit-based widget) replaces the Qutepart-backed `Markoff::Source::SourceEditor`.
- `Markoff::MarkdownView` polymorphic base, redefined for the three concrete consumers (live edit, live read-only, source).
- `Markoff::MarkoffDocument` consumer surface reshaped (Section 4.2).
- Library renames and reorganisation (Section 3).
- `MarkoffParser::MarkoffParser` namespace renamed to `Markoff::Parser`.
- Branch / merge mechanics through to `v1.0.0` tag (Section 6).
- Corbomite migration guide as a co-deliverable (Section 7).

### 2.2 Explicitly out of scope (deferred to v1.1+)

- Inline styling rendering (bold / italic / inline code / strikethrough rendered as styled text).
- Delineator hiding (cursor-aware suppression of `**`, `` ` ``, etc.).
- Tables (pipe tables remain rendered as paragraphs of literal source text).
- D5 / collab activation. Markoff v1.0 ships single-user local. The D5 stub spec stays in `docs/specs/2026-05-04-d5-collab-activation-STUB.md`.
- The C1 DI seam: `LinkResolver`, `Vault::MetadataCache`, `Vault::MetadataParser`, `EmbedRegistry`, `CodeBlockRegistry`, `MermaidRenderer` — none of these abstractions return. Corbomite keeps its concrete implementations Corbomite-side.
- Hover-popover wiki-link previews via a dedicated reading widget. Corbomite may continue to use `Live::Editor` in read-only mode for hover previews, but Markoff does not provide a specialised popover-mode renderer.

These omissions cause visible regressions in Corbomite for the duration between v1.0 and v1.1; that is an accepted cost.

## 3. Library structure

The v1.0 tree is four libraries plus the parser:

| Library | Public namespace | Purpose | Source |
|---|---|---|---|
| `markoff-parser` | `Markoff::Parser` | Tree-sitter Markdown AST + YAML frontmatter. | Renamed namespace from `MarkoffParser::MarkoffParser`; library directory unchanged. |
| `markoff-core` | `Markoff::` (consumer types) and `Markoff::Core::` (CRDT internals) | Per-block CRDT `MarkoffDocument`, `Cmd::*` commands, `BlockId`, `IdList`, `UndoLog`, `applyFlatEdit`, the `MarkdownView` polymorphic base, and shared types (`CursorPos`, `Theme`, `EditorContext`, `ActionId`, `BlockKind`). Consumer-facing primitives live in `Markoff::` matching v0.x convention; advanced CRDT internals live in `Markoff::Core::`. | Renamed from `markoff-foundation`. |
| `markoff-live` | `Markoff::Live` | QML scene + `LiveListModelBinding` + new QWidget facade `Markoff::Live::Editor`. | Combined from `markoff-live-render`; QWidget facade is new code. |
| `markoff-source` | `Markoff::Source` | QPlainTextEdit-based source editor `Markoff::Source::Editor`. | Renamed from `markoff-source-widget`. |
| **DELETED** `markoff-view-qml` | — | Retired in D4 for live mode; the source-only remainder is superseded by `markoff-source`. | Removed in v1.0 prep. |

### 3.1 Public include paths

- `<markoff/parser/...>`
- `<markoff/core/...>`
- `<markoff/live/...>`
- `<markoff/source/...>`

No `<markoff/foundation/...>`, no `<markoff/live-render/...>`, no `<markoff/source-widget/...>`. Every public include changes; private includes inside each library may move at the implementer's discretion.

### 3.2 Inter-library dependencies

```
markoff-parser   ←  markoff-core
markoff-core     ←  markoff-live, markoff-source
```

`markoff-live` and `markoff-source` are siblings and do not depend on each other. `markoff-core` does not depend on Qt Quick — only on Qt Widgets, Qt Core, Qt Gui. `markoff-live` depends on Qt Quick + Qt Quick Widgets (for the QQuickWidget facade).

### 3.3 Standalone build invariant (preserved)

Per the existing family invariant, a fresh checkout must build green standalone with no host project present. CMake option `MARKOFF_READING_USE_REAL_COREDEPS` is removed (it was a Phase B bridge for the now-deleted reading widget).

## 4. Public API surface

The full canonical signatures live in Appendix A. This section gives the consumer's-eye-view summary and the rationale for the small number of consumer-visible decisions.

### 4.1 `Markoff::MarkdownView` — polymorphic base

`MarkdownView` is a concrete `QWidget` (not an abstract interface) defined in `markoff-core`. It is the base of `Markoff::Live::Editor` and `Markoff::Source::Editor`. Reading-mode is not a separate subclass — see §4.4.

The base contract is intentionally small: document attachment, cursor position (1-based line/column, the one consumer-facing convention shared with the v0.x line), scroll position (visual-line float, preserved from v0.x), read-only toggle, and capability probes (`hasCursor`, `hasEditing`).

### 4.2 `Markoff::MarkoffDocument`

`MarkoffDocument` lives in the `Markoff::` namespace (matching v0.x convention) and is implemented in the `markoff-core` library. The per-block CRDT internals — `iterateBlocks`, `blockText`, `blockKind`, `Cmd::*` (in the `Markoff::Core::` namespace), `applyFlatEdit`, `d2ApplyBufferEdit` — remain public for advanced consumers and for the live widget's binding code. They are not part of the consumer-facing UI surface; Corbomite does not call them.

The consumer-facing surface is small:

```cpp
QString  toMarkdown() const;
void     loadFromMarkdown(QString);
bool     isReadOnly() const;
void     setReadOnly(bool);
signals:
    void documentChanged();    // any content change, no offset args
    void documentReloaded();   // full content swap
```

**Decision: drop the linear `contentsChanged(offset, removed, inserted)` signal.** The per-block CRDT cannot cheaply produce linear offsets, and the only consumer-facing use of that signal in v0.x was `NoteDocument::onTextChanged` setting `modified = true` and re-emitting. A no-arg `documentChanged()` is sufficient. Cost to Corbomite: a one-line slot signature change.

### 4.3 `Markoff::Live::Editor`

The live widget. A `QWidget` that internally hosts a `QQuickWidget`, which renders the existing QML scene (`LiveView.qml` and the per-kind delegates). Public interface:

- All `MarkdownView` overrides.
- `void setViewTheme(const Theme&)`.
- `EditorContext context() const` and `void contextChanged(EditorContext)` signal — see §4.5.
- Link emission: `linkClicked(QString href, Qt::KeyboardModifiers)`, `linkHovered(QString href, QPoint globalPos)`.
- Image source resolution: `imageSourceRequested(QString relPath, QString token)` signal + `provideImageSource(QString token, QString resolvedPath)` slot. Asynchronous-by-design so the host can resolve via vault/file-system without blocking.
- Toolbar-driven formatting: `void action(ActionId)` and the `ActionId` enum (`Bold`, `Italic`, `InlineCode`, `Strikethrough`, `HeadingLevel(0..6)`, `Blockquote`, `BulletedList`, `NumberedList`, `TaskList`, `IndentMore`, `IndentLess`, `Link`, `Image`, `HorizontalRule`, `InsertTable`, `DeleteRow`, `DeleteColumn`). The set is the v0.x ActionId carried forward.

Read-only mode is the same widget with `setReadOnly(true)` — see §4.4.

### 4.4 Reading mode

There is no `ReadingView` class. Three Corbomite call sites that today instantiate `Markoff::Reading::ReadingView` migrate to `Markoff::Live::Editor` constructed with `setReadOnly(true)`:

1. `NoteEditorWidget`'s tri-view: stack index 2 becomes `Live::Editor` with `setReadOnly(true)`.
2. `HoverPopover`'s wiki-link preview: a `Live::Editor` instance with `setReadOnly(true)` and a fixed-width container.
3. `MarkdownRenderer::render` plugin verb: instantiates a `Live::Editor` with `setReadOnly(true)` for the render duration.

`hasCursor()` / `hasEditing()` return `false` when `isReadOnly()` is `true`, so callers can probe the widget exactly as they do today.

### 4.5 `EditorContext`

A slim struct delivered via `Live::Editor::contextChanged`:

```cpp
struct EditorContext {
    QString blockKind;            // canonical kind name; see §9 for built-in values
    int     headingLevel;         // 1..6 if blockKind == "heading", else 0
    bool    inTable;              // false in v1.0 (tables not rendered), reserved
    int     tableRow;             // -1 in v1.0
    int     tableCol;             // -1 in v1.0
};
```

The `blockKind` field is a `QString` rather than the closed `BlockKind` enum so that plugin-registered block types (a v1.1+ horizon — see §9) can flow through this struct without breaking the v1.0 contract. The eight v1.0 built-in kind names are: `"paragraph"`, `"heading"`, `"list-item"`, `"code-block"`, `"blockquote"`, `"image"`, `"math"`, `"horizontal-rule"`. Markoff publishes these as `Markoff::BlockKindNames::*` constants for consumers that prefer not to inline string literals.

In-span detection (`inBold`, `inItalic`, etc.) is **deferred to v1.1**; it depends on inline-styling work. Toolbar buttons for bold/italic/code can still fire `action(...)` to insert markers, but they will not display a "current state" until v1.1. The `EditorContext` struct is forward-extensible; v1.1 adds fields without breaking the v1.0 contract.

### 4.6 `Markoff::Source::Editor`

Same shape as `Live::Editor` minus link emission and image-source slots. `MarkdownView` overrides plus `setViewTheme`. Find-bar and replace-bar virtuals (`showFindBar()`, `showReplaceBar()`, `hideFindBar()`) live on `MarkdownView` for symmetry across leaves.

## 5. Live widget completion

Two distinct work areas live in `markoff-live`: **performance** and **link handling**. They share files but the changes are largely independent.

### 5.1 Performance

The pathology in `LiveListModelBinding::onD2Changed()` (today at `libs/markoff-live/src/LiveListModelBinding.cpp:127–308`) is a full-document walk on every keystroke: `iterateBlocks()` over all blocks, per-block `blockText` / `inlineSpansFor` / `blockAttrs` queries, then a Myers diff over the whole list, then a kind-transition re-entry check that can re-fire the entire pass. This is O(N) per keystroke with high constants, and combines with eager TextEdit instantiation, synchronous startup parse, and synchronous Image decoding to produce the observed 1-minute / 2GB / pegged-CPU symptoms.

**Strategy in three layers:**

1. **Targeted updates from the CRDT.** `MarkoffDocument` already routes `Cmd::*` through known `BlockId`s and knows which blocks were touched. Replace the full-walk handler with a signal that carries touched block IDs (e.g. `blocksChanged(QList<BlockId>)`, `blockInserted(BlockId, int row)`, `blockRemoved(BlockId, int row)`). The model emits `dataChanged(index)` for the touched blocks and `rowsInserted/Removed` for structural changes. No Myers diff in the common keystroke case.

2. **Move kind-transition detection out of the hot path.** Run kind inference only when the touched block's text crosses a known boundary marker (paragraph gains a leading `# `, list item loses its `- ` prefix, etc.). The signal carrying touched IDs can carry a hint flag from the command layer.

3. **Stop fetching `inlineSpansFor` until v1.1.** It is gathered and discarded today (the QML delegates do not consume it). Drop the call from per-block extraction; reintroduce when delegates begin consuming spans for inline styling.

**Smaller fixes:**

- `Image { asynchronous: true }` per `ImageDelegate.qml` — single-line fix, removes main-thread image-decode stalls.
- Defer the document load to after first frame paint: in `app/main.cpp` (and the new QWidget facade), call `loadFromMarkdown` from a `QTimer::singleShot(0, ...)` or `QQuickWindow::afterRendering` callback so the window is visible before the parse runs.
- Audit ListView's `cacheBuffer` / `displayMarginBeginning` / `displayMarginEnd` to keep off-viewport delegate count bounded.

**Definition of done.** A 500-line markdown document opens with the window visible in ≤500 ms, peak RSS ≤300 MB, idle CPU between keystrokes ≤2%. Measured by a perf benchmark in `tests/perf/` that runs in CI on a fixed reference document.

### 5.2 Link handling

Inline link spans are already produced by the parser (`inlineSpansFor` returns them). The QML delegates do not currently consume any inline span. Build the minimum inline-runs scaffold the delegates need, but only wire **link** spans to interaction:

- Per-block delegate (Paragraph, Heading, ListItem, Blockquote) consumes the `linkSpans` subset of `inlineSpans` (filter to `link` / `wikilink` / `autolink` types only).
- Render link runs as styled (themed colour + underline) using `Text { textFormat: Text.RichText }` over the source text, masking only the link spans. Non-link spans render as plain literal markdown — bold/italic markers stay visible until v1.1.
- Hover and click detection via per-link `MouseArea` overlays. Link rectangles are computed from `TextEdit.positionToRectangle` for the start and end positions of each span; `MouseArea` instances are dynamically instantiated per link in the block.
- C++ side: `LiveListModelBinding` exposes two QML-invokable methods, `onLinkClicked(QString href, int modifiers)` and `onLinkHovered(QString href, QPoint global)`, that re-emit on the `Live::Editor` facade as the public signals.

The inline-runs scaffold built here is the same scaffold v1.1 inline styling will need; building it now unblocks v1.1 cheaply.

**Image source resolution** is wired through the same QML-↔-C++ bridge: `ImageDelegate.qml` requests its source via a token, the C++ binding emits `imageSourceRequested(relPath, token)`, the host calls `provideImageSource(token, resolvedPath)` once resolved, and the binding plumbs the resolved path back to the delegate.

### 5.3 QWidget facade

`Markoff::Live::Editor` is a `QWidget` that owns a `QQuickWidget` child filling its layout. The QQuickWidget loads `LiveView.qml` from a Qt resource compiled into `markoff-live`. The C++ classes (`LiveListModelBinding`, `LiveCursorState`, etc.) are exposed via `QQuickWidget::rootContext()->setContextProperty(...)`. Public signals defined on the facade re-emit the QML/binding signals through Qt's metaobject system.

Known QQuickWidget caveats accepted as v1.0 trade-offs: render-to-FBO causes per-frame readback; tearing-free vsync may be looser than a dedicated QQuickView. These are documented in the migration guide for the Corbomite team.

## 6. Branch, merge & release mechanics

1. **Work lands on `foundation-exploration`** as a sequence of work-unit PRs. Each unit is its own commit/PR with the test suite green.
2. **API freeze** is a labelled commit on `foundation-exploration` once the public surface in §4 is implemented. The migration guide (§7) is finalised against that commit. The Corbomite team can begin adapting in parallel from this point.
3. **Merge to `main`** happens once all v1.0 work units are complete and tests are green. `foundation-exploration` becomes `main`'s tip via fast-forward or merge commit; D-arc history is preserved.
4. **Tag `v1.0.0`** on `main` after the merge. Per family invariant, never force-push tags.
5. **Corbomite bumps** its submodule reference to `v1.0.0` once Corbomite's adaptation branch is ready. Coordinated swap.

`master` is left untouched after the swap — its history is preserved per the family append-only invariant. `master` is no longer the active branch; new work targets `main`.

- The 103 existing tests remain green.
- New tests cover:

**Post-merge dogfooding.** Ongoing Markoff development uses Corbomite as the real-world test environment alongside `markoff-testapp`. The dedicated test app remains the canonical place for tightly-controlled unit-style UI tests; Corbomite is the integration / behaviour-in-anger test bed.

## 9. Extensibility horizon

This section is **non-binding**. It is a horizon scan, not a contract. v1.0 ships with **zero** plugin-extension API. The purpose of this section is to record the v1.1+ extension capabilities that are likely to be wanted by Corbomite plugins, and to capture the v1.0 design decisions made specifically to keep those extensions a *non-breaking* change later.

### 9.1 Likely v1.1+ extension capabilities

Corbomite has a plugin system. Plausible plugin-driven extension points for the Markoff widget family:

1. **Custom block kinds.** Plugins register new block-kind names (e.g. `"callout"`, `"dataview-query"`, `"audio-recording"`) plus a QML delegate component to render them and a parser hook to recognise the markdown that produces them.
2. **Code-block language renderers.** Plugins register renderers for code blocks of a given language tag (e.g. mermaid, vega, abc-notation). Replaces the v0.x `CodeBlockRegistry` mechanism but on the live widget rather than a dead Reading widget.
3. **Inline embed renderers.** Plugins render `![[…]]` and similar inline embeds as something richer than text — file previews, web bookmark cards, etc. Replaces v0.x `EmbedRegistry`.
4. **Block decorations / overlays.** Plugins draw non-content visual elements on existing blocks: lint underlines, sync-status banners, plugin-driven highlights.
5. **Toolbar / context-menu extensions.** Plugins add custom `ActionId` values, custom right-click items, custom keybindings.

### 9.2 v1.0 decisions made to preserve future extensibility

These choices were taken consciously to keep v1.1+ extensibility a non-breaking, additive change:

- **`EditorContext::blockKind` is a `QString`, not a closed enum.** Plugin-defined block kinds flow through `EditorContext` without breaking the v1.0 contract (§4.5).
- **Signals-out integration with no DI seam.** Adding registration calls (`registerBlockKind(...)`, `registerCodeBlockRenderer(...)`, etc.) to `Live::Editor` later is purely additive and has no impact on existing consumers.
- **`DelegateChooser` already in place in the QML scene.** Adding a hook for plugin-registered delegates is mechanical; the dispatch primitive exists.
- **The `ActionId` enum is treated as a versioned but extensible registry.** v1.0 publishes a fixed set; v1.1+ may add values without breaking existing callers (Qt's `Q_ENUM` machinery handles unknown values gracefully).
- **Internal `BlockRecord.kind` is already a `QString`** in foundation-exploration's binding code, so the parser→model→delegate path doesn't require structural changes to admit plugin kinds.

### 9.3 Decisions explicitly *not* made in v1.0

These are flagged to be designed against in a v1.1+ extensibility spec, not now:

- The exact registration API shape (`registerBlockKind` signature, lifetime semantics, conflict resolution if two plugins register the same name).
- How plugin-provided QML files are loaded (Qt resource, file system, `QQmlComponent` factory).
- Plugin access to internal `MarkoffDocument` types (read-only handle? full API? a sandboxed view?).
- Decoration provider z-ordering, overlay coordinate spaces, and composition rules.
- Any cross-cutting plugin-cleanup contract (the v0.x `detachLeavesOfType` pattern Corbomite uses today on plugin disable).

### 9.4 Relationship to the C1 DI seam

The v1.0 spec explicitly cuts the C1 DI seam (`LinkResolver`, `MetadataCache`, `MetadataParser`, `EmbedRegistry`, `CodeBlockRegistry`, `MermaidRenderer`). The v1.1+ extension API is **not** a resurrection of the C1 seam. The C1 seam was an injection-from-host pattern designed around a Reading widget that no longer exists; the v1.1+ extension API will be a registration-from-plugins pattern designed around the live widget that does. Different shape, different audience, different lifecycle.

## Appendix A — Canonical API contract

The full v1.0 public surface in header form. This appendix is copied verbatim into the migration guide so the two documents cannot diverge.

```cpp
// markoff-core / include/markoff/core/CursorPos.h
namespace Markoff {
    struct CursorPos { int line = 1; int column = 1; };  // 1-based
}

// markoff-core / include/markoff/core/Theme.h
namespace Markoff {
    class Theme { /* opaque to consumers; passed by value */ };
}

// markoff-core / include/markoff/core/EditorContext.h
namespace Markoff {
    // Canonical kind names for v1.0 built-in block kinds. Consumers may use
    // these constants or inline string literals; either is API-stable.
    namespace BlockKindNames {
        constexpr auto Paragraph      = "paragraph";
        constexpr auto Heading        = "heading";
        constexpr auto ListItem       = "list-item";
        constexpr auto CodeBlock      = "code-block";
        constexpr auto Blockquote     = "blockquote";
        constexpr auto Image          = "image";
        constexpr auto Math           = "math";
        constexpr auto HorizontalRule = "horizontal-rule";
    }
    struct EditorContext {
        QString blockKind = BlockKindNames::Paragraph;
        int     headingLevel = 0;
        bool    inTable = false;
        int     tableRow = -1;
        int     tableCol = -1;
    };
}

// markoff-core / include/markoff/core/ActionId.h
namespace Markoff {
    enum class ActionId {
        Bold, Italic, InlineCode, Strikethrough,
        HeadingLevel0, HeadingLevel1, HeadingLevel2,
        HeadingLevel3, HeadingLevel4, HeadingLevel5, HeadingLevel6,
        Blockquote, BulletedList, NumberedList, TaskList,
        IndentMore, IndentLess,
        Link, Image, HorizontalRule,
        InsertTable, DeleteRow, DeleteColumn,
    };
}

// markoff-core / include/markoff/core/MarkoffDocument.h
namespace Markoff {
    class MarkoffDocument : public QObject {
        Q_OBJECT
    public:
        explicit MarkoffDocument(QObject* parent = nullptr);

        QString toMarkdown() const;
        void    loadFromMarkdown(QString);
        bool    isReadOnly() const;
        void    setReadOnly(bool);

        // Per-block CRDT API (advanced; live widget binds to this internally).
        // Includes iterateBlocks, blockText, blockKind, Markoff::Core::Cmd::*,
        // applyFlatEdit, d2ApplyBufferEdit, BlockId, IdList, UndoLog.
        // Specifics inherited from foundation-exploration without
        // consumer-facing change. Cmd::* and other CRDT-internal types live
        // in the Markoff::Core:: namespace.

    signals:
        void documentChanged();
        void documentReloaded();
    };
}

// markoff-core / include/markoff/core/MarkdownView.h
namespace Markoff {
    class MarkdownView : public QWidget {
        Q_OBJECT
    public:
        explicit MarkdownView(QWidget* parent = nullptr);

        virtual void setDocument(Markoff::MarkoffDocument*);
        virtual Markoff::MarkoffDocument* document() const;

        virtual Markoff::CursorPos cursorPosition() const;
        virtual void setCursorPosition(Markoff::CursorPos);

        virtual float scrollPositionVisualLine() const;
        virtual void  setScrollPositionVisualLine(float);

        virtual void setReadOnly(bool);
        virtual bool isReadOnly() const;

        virtual bool hasCursor()  const { return false; }
        virtual bool hasEditing() const { return false; }

        virtual void showFindBar();
        virtual void showReplaceBar();
        virtual void hideFindBar();

    signals:
        void documentChanged(Markoff::MarkoffDocument*);
        void cursorPositionChanged(int line, int column);
        void scrollPositionChanged(float);
    };
}

// markoff-live / include/markoff/live/Editor.h
namespace Markoff::Live {
    class Editor : public Markoff::MarkdownView {
        Q_OBJECT
    public:
        explicit Editor(QWidget* parent = nullptr);
        ~Editor() override;

        bool hasCursor()  const override { return true; }
        bool hasEditing() const override { return !isReadOnly(); }

        void setViewTheme(const Markoff::Theme&);
        Markoff::EditorContext context() const;

        void action(Markoff::ActionId);

    public slots:
        void provideImageSource(QString token, QString resolvedPath);

    signals:
        void linkClicked(QString href, Qt::KeyboardModifiers);
        void linkHovered(QString href, QPoint globalPos);
        void imageSourceRequested(QString relPath, QString token);
        void contextChanged(Markoff::EditorContext);
    };
}

// markoff-source / include/markoff/source/Editor.h
namespace Markoff::Source {
    class Editor : public Markoff::MarkdownView {
        Q_OBJECT
    public:
        explicit Editor(QWidget* parent = nullptr);
        ~Editor() override;

        bool hasCursor()  const override { return true; }
        bool hasEditing() const override { return !isReadOnly(); }

        void setViewTheme(const Markoff::Theme&);
    };
}
```

## Appendix B — Open questions for implementation phase
