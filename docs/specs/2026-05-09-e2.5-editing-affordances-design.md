## 1. Scope

E2.5 turns Markoff Live from "you can type into it" into "you can use it as an editor." Three of the work items are dogfood-blocking (clipboard, save, session-subscription); the rest are table-stakes word-processor affordances.

The phase has **seven deliverables sharing a single QAction surface**:

1. **Cut / Copy / Paste** of Markdown source bytes (and a structured Markoff payload for cut-paste-back identity preservation).
2. **`LiveActionController`** — single per-binding action collection consumed by menu bars, toolbars, the context menu, and `Keys.onPressed`.
3. **Right-click context menu** populated from the action collection (Cut/Copy/Paste/SelectAll/Undo/Redo/UndoForBlock).
4. **Format toggles** — Ctrl+B (bold), Ctrl+I (italic), Ctrl+K (link), per-block independent application, idempotent.
5. **Save / dirty / window title** — `Ctrl+S` writes to the load path; `MarkoffDocument` exposes a save-watermark API; `markoff-live-app` reflects modified state in the title.
6. **Cross-view session state — Live side bidirectional.** `LiveSelectionView` subscribes to `Session::primarySelectionChanged`. `markoff-live-app` instantiates a `Session`.
7. **Empty-doc focus + first-keystroke materialisation** — explicit test pass; fix any edge cases.

All seven sit in one spec because the QAction surface and the selection-pipeline contract are cross-cutting: clipboard, format toggles, and undo/redo all consume the same selection state and all expose actions through the same controller. Splitting forces those contracts to be re-derived in sibling specs.

### 1.1 Why one unified spec

The action collection is the integration seam. Splitting clipboard from format-toggles from save would mean designing the action controller three times — once per spec, with each missing the others' constraints. The session-subscription work is small enough on its own to fold in cleanly, and pairs naturally with the test-app harness work that save/dirty needs. Empty-doc is a half-day verification pass.

### 1.2 What does NOT ship in E2.5

- **Theming wire-up** (E2.6). Delegates continue to hardcode their base font sizes.
- **Zoom / `fontScale`** (E2.6). No `Ctrl+=` / `Ctrl+-` / `Ctrl+wheel`.
- **Speculative open-delimiter / code-fence styling** (E2.7).
- **Save-As / New / Open** dialogs. `markoff-live-app` continues to take a single file path on argv; `Ctrl+S` writes back to that path; nothing else.
- **Cross-view scroll-position handoff** and **folded-region handoff**. Folding isn't implemented in Live; scroll-restore on view-swap isn't dogfood-blocking. Re-opens to E2.5b (or later) if dogfood surfaces friction.
- **Untitled-document state machine.** No "(untitled)" doc, no "modified close" prompt.
- **`text/markdown` MIME on the clipboard.** Round-trip stability isn't proven; we ship `text/plain` + a structured Markoff payload only. Defer to a follow-up when round-trip is validated.
- **Find / Replace / Goto-line** — out of E-arc framing, not E2.5-specific.

## 2. Architecture

### 2.1 Layer placement

E2.5 spans L3 (cursor + selection), L4 (block editing), and L5 (structural keys) of the markoff-live stack. No L0–L2 changes; the action / format / clipboard controllers consume `LiveBlockModel`, `LiveSelectionView`, and `MarkoffDocument` through their existing APIs.

A small surface lands in `markoff-core`:

- `MarkoffDocument::savedSequence()`, `markSaved(quint64)`, `dirtyChanged(bool)` — save-watermark API.
- `MarkoffDocument::applyStructuredPaste(const Selection &replaceRange, const QJsonArray &blocks, const PasteMeta &meta)` — paste fast-path that reuses `BlockId`s when the source matches a recent local cut.

### 2.2 Components

| Component | New / Existing | Responsibility |
|---|---|---|
| `LiveClipboardController` | **new** in `libs/markoff-live` | `cut()` / `copy()` / `paste()` against current `LiveSelectionView` + `MarkoffDocument`. Owns clipboard MIME read/write. Detects local-cut MIME and routes paste through the structure-aware fast-path; otherwise routes through `applyFlatEdit`. |
| `LiveActionController` | **new** in `libs/markoff-live` | Holds the `QAction`s. Wires `triggered` to controller methods. `enabled` of each action is bound to predicates (selection nonempty, clipboard nonempty, etc). Q_PROPERTY per action so QML and host menu bars consume identically. |
| `LiveFormatController` | **new** in `libs/markoff-live` | `toggleBold()` / `toggleItalic()` / `insertLink()` against current selection. Per-block independent application; idempotent (detects existing wrapping and unwraps). |
| `LiveListModelBinding` | **modified** | Owns + exposes `clipboardController`, `actionController`, `formatController`. Wires them in ctor. |
| `LiveSelectionView` | **modified** | New `Q_INVOKABLE void selectAll()`. New private slot `applySessionSelection(const Selection &)` subscribed to `Session::primarySelectionChanged`, guarded by existing `m_applyingSessionSelection`. New `Q_INVOKABLE void deleteSelection()` for the structure-aware paste path's replace step. |
| `LiveContextMenu.qml` | **modified** | Cut / Copy / Paste / SelectAll / separator / Undo / Redo / separator / "Undo in this block". All driven from the action controller. |
| `LiveView.qml` | **modified** | Drop the ad-hoc Ctrl+C `Keys.onPressed` block; shortcuts now ride the QActions. Keep mouse routing. |
| `MarkoffDocument` | **modified** | New `savedSequence()`, `markSaved(seq)`, `dirtyChanged(bool)`. New `applyStructuredPaste(...)`. |
| `markoff-live-app/main.cpp` | **modified** | Construct `Session` via `MarkoffDocument::createSession`, hand to binding. Expose `Save` action to a `QFile` write callback that calls `markSaved`. Update window title from `dirtyChanged`. |

### 2.3 Why a sibling controller and not methods on the binding

`LiveListModelBinding` is already the largest class in the leaf and is the integration nexus for the model, cursor, structural keys, edit binding, and selection. Adding ~10 actions + Cut/Copy/Paste/Format methods directly to the binding would push it past readable; sibling controllers keep responsibilities narrow and make each unit testable in isolation. The binding holds them and exposes Q_PROPERTYs; QML reads `binding.actionController.cutAction` rather than `binding.cutAction`. One indirection, large readability win.

## 3. Clipboard pipeline

### 3.1 MIME types written

Cut and Copy write **two** entries to the system clipboard:

- `text/plain` — the rendered text, joining block texts with `\n` (matches today's `LiveSelectionView::copyToClipboard`). Empty-block boundaries become single-newline.
- `application/x-markoff-blocks` — JSON payload (see §3.2).

`text/markdown` is **not** written. Round-trip parity isn't proven; revisit when it is.

### 3.2 `application/x-markoff-blocks` payload

```json
{
  "version": 1,
  "sourceReplicaId": 12345,
  "cutSequenceNumber": 42,
  "blocks": [
    { "kind": "Heading", "text": "## Section", "attrs": { "level": 2 } },
    { "kind": "Paragraph", "text": "Body text spanning a partial selection." }
  ]
}
```

- **`version`** — schema version. `1` for E2.5. Future schema breaks bump and add a migration path.
- **`sourceReplicaId`** — `MarkoffDocument::replicaId()` of the doc that produced the cut/copy.
- **`cutSequenceNumber`** — set on Cut to `MarkoffDocument::d2EditSequence()` immediately *before* the cut applies; absent on Copy. Lets paste detect "this came from us" + "this exact cut, not a stale copy of it" for the BlockId-reuse fast-path.
- **`blocks`** — array of partial-or-whole block snapshots. Each entry carries `kind`, `text` (post-clipping per the existing `rangeForBlock` semantics), and `attrs` (kind-specific: `level` for headings, `language` for code blocks, `marker` for list items, etc).

The payload is structure-aware but **does not** carry CRDT state — IDs are document-internal. Identity preservation rides on the `(sourceReplicaId, cutSequenceNumber)` pair plus an index into a short-lived in-doc cache of recently-cut block IDs.

### 3.3 Paste path — hybrid

1. `LiveClipboardController::paste()` reads `application/x-markoff-blocks`. If present, parse + version-check.
2. If parse succeeds and `sourceReplicaId == document->replicaId()` and `cutSequenceNumber` matches a still-cached recent local cut → call `MarkoffDocument::applyStructuredPaste(replaceRange, blocks, {.reuseBlockIds = true, .cutSeq = cutSequenceNumber})`.
3. Else if parse succeeds (foreign Markoff payload, or local copy with no sequence number) → call `applyStructuredPaste(replaceRange, blocks, {.reuseBlockIds = false})`. Kinds + attrs are honored; new BlockIds are minted.
4. Else (no Markoff MIME, or parse failed) → fall back to `applyFlatEdit(rangeStart, rangeEnd, plainText)`. Multi-block paste re-derives kinds via `inferBlockKind` automatically. Identical to the existing flat-text source-widget path.

The cached-cuts table in `MarkoffDocument` is bounded (e.g. last 8 cuts), with each entry holding `{cutSeq, blockIds[]}`. Entries age out on next cut or on document destruction. No serialization.

### 3.4 Cut

`cut()` = `copy()` + `selectionView->deleteSelection()`. `deleteSelection` routes through the existing edit pipeline (`d2ApplyBufferEdit` / structural-key delete-merge for cross-block) so the post-cut state is identical to "user selected and pressed Delete." The `cutSequenceNumber` written to the MIME payload is captured *before* the deletion so paste can match it.

A cut that empties the document (every block selected and cut) leaves a single empty Paragraph block — see §9 (empty-doc handling).

### 3.5 Tests

- `tst_live_render_clipboard_copy` — extend with Markoff-MIME presence assertions; verify JSON payload schema.
- `tst_live_render_clipboard_cut` — new. Cut empties selection; document state matches a Delete-key path.
- `tst_live_render_clipboard_paste_flat` — new. Foreign clipboard (no Markoff MIME) routes through `applyFlatEdit`; multi-block markdown re-derives kinds.
- `tst_live_render_clipboard_paste_structured` — new. Local cut → paste → block IDs reused; kinds + attrs preserved.
- `tst_live_render_clipboard_paste_foreign_markoff` — new. Markoff MIME from a different replica → structured payload honored, new IDs minted.
- `tst_live_render_clipboard_round_trip` — new. Multi-block selection → Cut → Paste at a different position → semantic content preserved.

## 4. Action surface

### 4.1 `LiveActionController`

Holds eleven `QAction`s, owned by `LiveListModelBinding`:

| Action | Default shortcut | Triggered → | Enabled when |
|---|---|---|---|
| `cutAction` | `Ctrl+X` | `clipboardController->cut()` | `selectionView->hasSelection` |
| `copyAction` | `Ctrl+C` | `clipboardController->copy()` | `selectionView->hasSelection` |
| `pasteAction` | `Ctrl+V` | `clipboardController->paste()` | clipboard has `text/plain` or `application/x-markoff-blocks` |
| `selectAllAction` | `Ctrl+A` | `selectionView->selectAll()` | document has at least one block |
| `deleteAction` | `Delete` | `selectionView->deleteSelection()` | `selectionView->hasSelection` |
| `undoAction` | `Ctrl+Z` | `document->undoD2()` | `document->canUndoD2()` |
| `redoAction` | `Ctrl+Shift+Z` | `document->redoD2()` | `document->canRedoD2()` |
| `boldAction` | `Ctrl+B` | `formatController->toggleBold()` | `selectionView->hasSelection` |
| `italicAction` | `Ctrl+I` | `formatController->toggleItalic()` | `selectionView->hasSelection` |
| `linkAction` | `Ctrl+K` | `formatController->insertLink()` | always |
| `saveAction` | `Ctrl+S` | emits `saveRequested()` | `document->dirty()` (host-overridable) |

Each is a Q_PROPERTY so QML and host menu bars observe enabled-state via the same binding.

`saveAction` does not write a file itself — `markoff-core` is I/O-free. The action emits a controller-level `saveRequested()` signal; the host (markoff-live-app or Corbomite) wires it to its own write path and calls `MarkoffDocument::markSaved(d->d2EditSequence())` on success.

### 4.2 Shortcut delivery

Actions are added to the `QQuickWindow` via `addAction()`. Shortcuts ride `Qt::WindowShortcut` context. The ad-hoc `Keys.onPressed` Ctrl+C handler in `LiveView.qml` is removed — the action collection owns shortcuts.

`QClipboard::dataChanged` is observed so `pasteAction.enabled` updates without a re-poll.

### 4.3 Tests

- `tst_live_render_actions_enabled_state` — for each action, drive selection / clipboard / undo-stack into states and assert `enabled`.
- `tst_live_render_actions_dispatch` — `trigger()` each action, assert the corresponding controller method ran (mock controller).
- `tst_live_render_clipboard_changed_updates_paste` — set system clipboard externally, assert `pasteAction.enabled` reflects within one event-loop turn.

## 6. Format toggles

### 6.1 Bold (`Ctrl+B`)

`formatController->toggleBold()` operates on current `LiveSelectionView` selection.

**Per-block independent application:**

For each block in the selection (single-block: just that block; multi-block: each block's per-block sub-range from `rangeForBlock`):

1. Resolve the byte range within the block's CRDT buffer.
2. Detect: is this exact range already wrapped by `**…**`? Use `BlockRecord::inlineSpans` (already present from E1) to check for a `bold` span covering the range.
3. **If wrapped** → unwrap. Issue an `applyFlatEdit` that removes the surrounding `**` pairs.
4. **If not wrapped** → wrap. Issue an `applyFlatEdit` that inserts `**` at start and end of the range.
5. After all blocks process, re-set the selection to span the new content (excluding the inserted markers, so the user can re-toggle).

Empty selection within a block → insert `****` and place caret between the two pairs (so the user can type bold text).

### 6.2 Italic (`Ctrl+I`)

Identical to bold but with `_..._` delimiters and the `italic` inline span. (CommonMark accepts both `*..*` and `_.._` for italic; we write `_..._` to avoid `*` collision with bold-marker-detection logic.)

### 6.3 Link (`Ctrl+K`)

`formatController->insertLink()`:

- **Selection within one block, nonempty** → wrap as `[selection](url)`. Caret goes inside `()`.
- **Empty selection** → insert `[](url)`. Caret goes inside `[]`.
- **Multi-block selection** → operate per-block independently (each block gets its own link wrap). Edge case: a multi-block selection where one block is a non-text-bearing kind (HR, Image) — skip those blocks.
- **No popup**, no QInputDialog. The user types the URL inline.

Idempotent: detecting an existing link wrap is harder than bold/italic (link spans can have arbitrary URLs); for E2.5 the rule is "if the *exact* selection is already inside a link's text, unwrap; else wrap." If the user wants something more sophisticated, they undo.

### 6.4 Tests

- `tst_live_render_format_bold_single_block` — wrap, idempotent unwrap, empty-selection caret-between-markers behavior.
- `tst_live_render_format_italic_single_block` — same shape, `_..._`.
- `tst_live_render_format_link_single_block` — empty selection → `[](url)` with caret in `[]`; nonempty → `[text](url)` with caret in `()`.
- `tst_live_render_format_multi_block` — Bold across three paragraphs → three independent wraps. Italic across heading + paragraph → both wrap. HR/Image in selection → skipped, surrounding blocks still wrap.
- `tst_live_render_format_idempotent` — Bold then Bold again on same selection → original text restored.

## 7. Save / dirty / window title

### 7.1 `MarkoffDocument` API additions

```cpp
class MarkoffDocument : public QObject {
    Q_OBJECT
public:
    quint64 savedSequence() const;
    void    markSaved(quint64 seq);
    bool    dirty() const;  // savedSequence() != d2EditSequence()
Q_SIGNALS:
    void    dirtyChanged(bool dirty);
};
```

- `markSaved(seq)` records the watermark. Caller passes the result of `d2EditSequence()` *captured before the file write started* (so an edit during the write is correctly reflected as still-dirty afterward).
- `dirtyChanged` fires on *transitions* — once when first becoming dirty, once when going clean. Not on every edit. Implemented as a guarded comparison in `d2DocumentChanged`'s slot and in `markSaved`.

### 7.2 `markoff-live-app/main.cpp`

- Construct `Session` via `MarkoffDocument::createSession(quint16 replicaId)`. Pass to `LiveListModelBinding::setSession()`.
- Connect `binding->actionController()->saveAction()->triggered` to a write lambda:
  - Capture `seq = doc->d2EditSequence()`.
  - Serialize via `doc->toMarkdownUtf8()`.
  - Open the load path (the argv file) in write+truncate mode, write bytes, close.
  - On success: `doc->markSaved(seq)`. On failure: log + leave dirty.
- Connect `doc->dirtyChanged` to update the `QQuickWindow::title`:
  - Title format: `<basename><dirty-marker> — markoff-live`
  - Dirty marker: `*` on Linux/Windows; `Modified` semantics on macOS via `QQuickWindow::setProperty("modified", dirty)` (Qt handles the platform-native indicator).
- On startup, after `loadFromMarkdown`, call `doc->markSaved(doc->d2EditSequence())` so the doc starts clean.

### 7.3 Tests

- `tst_markoff_doc_save_watermark` — markSaved → not dirty; edit → dirty; markSaved with new seq → not dirty.
- `tst_markoff_doc_dirty_changed_signal` — signal fires once per transition, not per edit.
- `tst_markoff_doc_save_during_edit_race` — capture seq before edit, edit, markSaved with old seq → still dirty.
- `markoff-live-app` save behavior is verified manually in dogfood (no Qt-test for the file-I/O layer; not worth the harness cost).

## 8. Live-side session subscription

### 8.1 Subscribe path

`LiveSelectionView` gains a private slot `applySessionSelection(const Markoff::Selection &sel)` connected to `Session::primarySelectionChanged` in `setSession()`.

The slot:

1. Skip if `m_applyingSessionSelection` (reentrancy guard already in the header — this is the read side that uses it).
2. Resolve `sel.anchor` and `sel.active` via `MarkoffDocument` to `(blockIndex, qtPos)` — invert the existing write-side `textAnchorAt` flow.
3. Clamp each `qtPos` to its block's text length.
4. If either anchor's `blockIndex` is no longer valid (block was deleted in a concurrent edit), clear selection and return.
5. Set `m_anchorBlock/m_anchorQtPos` and `m_activeBlock/m_activeQtPos`. Emit `selectionChanged`.

Reentrancy is protected by `m_applyingSessionSelection = true` around the assignment, so the resulting `selectionChanged` doesn't recurse into `syncToSession`.

### 8.2 Test app harness

`markoff-live-app/main.cpp` instantiates a `Session` and binds it. No QML changes required for E2.5 — the smoke test below is the contract that needs to hold.

### 8.3 Tests

- `tst_live_render_session_apply` — single binding subscribed to a Session; externally call `session->setPrimarySelection(...)` → `LiveSelectionView::hasSelection` becomes true, `rangeForBlock` returns the expected range.
- `tst_live_render_session_two_bindings` — two `LiveListModelBinding`s on the same doc + same Session. Selection in instance A is observable in instance B via `rangeForBlock`. (No real Source widget needed; this verifies the contract.)
- `tst_live_render_session_clamp` — Session selection past end-of-block → clamps to text length, no crash.
- `tst_live_render_session_orphaned_block` — Session selection on a BlockId that was deleted concurrently → selection clears.

- **Scroll position handoff** (`Session::setTopVisible(anchor, fraction)`). Folded out per scope doc; re-opens to E2.5b if dogfood needs it.
- **Folded-region handoff.** Folding isn't implemented in Live yet.

## 9. Empty-doc focus + first-keystroke materialisation

### 9.1 Definition

"Empty document" = exactly one `Paragraph` block containing zero bytes of text. (Zero blocks is not a representable state — `MarkoffDocument` invariants guarantee at least one block; empty-doc means that one block is empty.)

### 9.2 Required behaviors

1. Empty doc loaded → focus lands in the empty paragraph's `TextEdit` automatically. User can type without clicking.
2. First keystroke into an empty paragraph → the parser reclassifies on Equal-op (e.g. `#` then space → Heading 1) per existing `inferBlockKind` rules.
3. After Cut-everything → document collapses to one empty Paragraph; focus stays in it.
4. Backspace at offset 0 of the only-block (empty or not) → no-op (existing).
5. Paste into an empty doc → behaves identically to paste into any other position.

### 9.3 Tests

- `tst_live_render_empty_doc_focus` — load empty doc, simulate a key event, assert character lands in the (now non-empty) paragraph.
- `tst_live_render_empty_doc_kind_transition` — empty doc → type `# `, assert kind becomes `Heading`.
- `tst_live_render_cut_to_empty` — multi-block doc → Ctrl+A → Cut → assert document has one empty Paragraph and focus is in it.

## 10. Subtractability note

Per E-arc framing §5: each E2.x deliverable must publish a subtractability note saying how a view that doesn't need the new affordances can avoid the runtime cost.

E2.5's affordances are all wired through `LiveListModelBinding` properties:

- A view that doesn't need clipboard / format / actions instantiates a binding without calling the new controller getters. The controllers are constructed in the binding's ctor (cheap; no clipboard observation, no I/O); the cost is the ctor allocation only.
- For a true zero-cost subtraction, the binding accepts a `LiveListModelBinding::Capabilities` flag set in its ctor (or a builder option) that selects which controllers to instantiate. Default is "all"; reading-only views pass `{}` and the controllers are nullptr-bound.
- The action shortcut bindings (`addAction` on the window) only happen if `actionController` is non-null. A read-only embed in a Reading-style view sees no shortcuts.
- `LiveSelectionView::setSession` already accepts nullptr; views that don't run a Session pay zero subscription cost.
- `MarkoffDocument`'s save-watermark API has no hot-path cost — `dirtyChanged` only fires on transitions; `savedSequence` storage is one `quint64`.

Recipe-driven view construction (E6 distillation work) will formalize the capability-flag model. E2.5 ships the flag plumbing but leaves the recipe to E6.

## 11. Risk surface

### 11.1 Large multi-block paste

Pasting a 1000-block markdown document via `applyFlatEdit` re-derives every kind via `inferBlockKind`. The d2 cycle is tuned for keystroke-rate edits, not bulk inserts. Risk: visible UI freeze on the paste.

**Mitigation strategy (defer to plan time):**

- Measure first. `applyFlatEdit` perf bench at 100 / 500 / 1000 / 5000 blocks. Existing `markoff-bench-render` infra reused.
- If above ~100ms wall-clock at 1000 blocks → batch the kind-inference pass (single `Cmd::changeKind` per inference, not per block). If still slow → add a `MarkoffDocument::beginBulkApply()` / `endBulkApply()` pair that suppresses `d2DocumentChanged` until the end.
- If above ~500ms → re-think; possibly `applyStructuredPaste` becomes the default for any paste over a size threshold, regardless of MIME match.

Specific budget: paste of 1000 blocks should complete within 200ms wall-clock on the baseline dev machine. Plan-time gate.

### 11.2 Clipboard MIME read on platforms with strict permission models

Wayland and macOS expose stricter clipboard semantics than X11. `QClipboard::mimeData()` is mostly portable but Wayland has historically lagged. Risk is low (Markoff already uses `QClipboard::setText` without issue) but worth a smoke test on Wayland during dogfood.

### 11.3 Format-toggle idempotence on overlapping spans

If the user has a selection that partially overlaps an existing bold span (e.g. `**bo|ld** more text|`, where `|` are selection bounds), the toggle behavior is ambiguous. Spec rule: "exact match" — toggle unwraps only when the selection exactly bounds an existing span; otherwise wraps. The user undoes if they wanted something else. Plan time may add a more sophisticated rule if dogfood demands.

### 11.4 Recent-cuts cache lifetime

The in-doc cache of recently-cut block IDs (`{cutSeq, blockIds[]}`) is bounded at ~8 entries, aging out on next cut. A user who cuts then pastes after ~1 hour could miss the BlockId-reuse path; paste then routes through the `reuseBlockIds=false` path of `applyStructuredPaste`. Acceptable degradation; not a correctness issue.
