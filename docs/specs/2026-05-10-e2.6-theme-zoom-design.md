# E2.6 — Theme wire-up + zoom — design

**Date:** 2026-05-10
**Status:** Approved for plan-writing.
**Phase:** E-arc / E2.6.
**Driving doc:** `docs/handoff/2026-05-09-post-e2-scope.md` §2.E2.6.
**Predecessor:** `v0.7.0-e2.5` (Option B selection + setext support).

---

## 0. Problem

`Markoff::Theme` ships a full per-slot font/colour/multiplier surface
and `defaultLight()` / `defaultDark()` factories, but **only the
`InlineHighlighter` uses any of it**. Every `markoff-live` QML delegate
hardcodes its base font size and family:

| Delegate | Hardcoded |
|---|---|
| `ParagraphDelegate` | `font.pixelSize: 14` |
| `HeadingDelegate`   | switch on `headingLevel` → 28/24/20/18/16/14 |
| `BlockquoteDelegate`| `font.pixelSize: 14; font.italic: true` |
| `CodeBlockDelegate` | `font.family: "monospace"; font.pixelSize: 13` |
| `ListItemDelegate`  | marker `font.family: "monospace"; font.pixelSize: 14`; body `font.pixelSize: 14` |
| `MathDelegate`      | two spots, `monospace` / `13` |
| `ImageDelegate`     | caption `font.italic: true; font.pixelSize: 12` |
| `CodeBlockDelegate` | language tag `font.pixelSize: 11` (×2) |
| `RemoteCursorOverlay` | label `font.pixelSize: 9` |

`Theme::fontSizeMultiplier(Slot)` is **defined but never called by any
consumer**. There is also no zoom infrastructure: no `fontScale` /
`zoom` property, no `Ctrl+=` / `Ctrl+-` / `Ctrl+0` / `Ctrl+wheel`
handlers anywhere in the leaf.

Goal: route every text-bearing element through `Markoff::Theme`, add a
user-controllable per-binding `fontScale`, and ship a light/dark
toggle action.

---

## 1. Architecture decisions (locked in brainstorm 2026-05-10)

| # | Decision |
|---|---|
| D1 | `fontScale` lives **on `LiveListModelBinding`** as a `Q_PROPERTY(qreal fontScale READ WRITE NOTIFY)`. No new controller class. |
| D2 | `Theme` exposes a new convenience method `pixelSizeFor(Slot)` that combines font-role lookup + multiplier + pt→px. Delegates compute their effective size as `theme.pixelSizeFor(slot) * binding.fontScale`. |
| D3 | Light/dark toggle is a `QAction` on `LiveActionController` that **emits `themeToggleRequested(bool dark)`**. The action is signal-only — the host app catches the signal and decides which `Theme` to apply via `binding->setTheme(...)`. The library does not own the choice of which theme to use. |
| D4 | **Session-only persistence.** Both `fontScale` and the dark/light choice reset to defaults (1.0, light) on every app launch. No `QSettings` work in this phase. |
| D5 | **All text-bearing UI is in scope** — 5 main delegates + Math + ListItem marker + CodeBlock language tag + ImageDelegate caption + RemoteCursorOverlay label. Each routes through theme + fontScale. |

## 2. Theme API additions (`libs/markoff-core`)

### 2.1 New methods on `Markoff::Theme`

```cpp
class Theme {
public:
    // Existing API unchanged.

    // NEW: convenience getters. Combine font-role lookup,
    // fontSizeMultiplier(slot), and pt→px conversion.
    qreal   pixelSizeFor(Slot) const;
    QString familyFor   (Slot) const;

    // (isBold/isItalic already exist; delegates use them as-is.)
};
```

### 2.2 Slot → FontRole mapping (file-internal helper)

```cpp
namespace {
Theme::FontRole roleFor(Theme::Slot s) {
    using S = Theme::Slot; using R = Theme::FontRole;
    switch (s) {
        case S::Heading1: case S::Heading2: case S::Heading3:
        case S::Heading4: case S::Heading5: case S::Heading6:
            return R::Heading;
        case S::CodeBlock: case S::InlineCode: case S::Math:
            return R::Monospace;
        default:
            return R::Body;
    }
}
}
```

`Theme::pixelSizeFor` and `Theme::familyFor` are the only callers.

### 2.3 Implementation

```cpp
qreal Theme::pixelSizeFor(Slot s) const {
    QFont f = font(roleFor(s));
    qreal pt = f.pointSizeF() > 0 ? f.pointSizeF() : 11.0;
    qreal mul = fontSizeMultiplier(s);
    if (mul <= 0) mul = 1.0;
    return pt * mul * (96.0 / 72.0);  // logical px at 96 dpi
}

QString Theme::familyFor(Slot s) const {
    return font(roleFor(s)).family();
}
```

The 96/72 constant is intentional. Qt's QML font system multiplies
`font.pixelSize` by the screen's `devicePixelRatio` for HiDPI rendering;
this method returns logical pixels at the canonical 96 dpi base.

### 2.4 `defaultLight()` multiplier additions

`defaultLight()` already sets H1=1.8, H2=1.5, H3=1.3. **Add explicit
defaults so the new `pixelSizeFor` produces deterministic sizes for
every text-bearing slot:**

```cpp
t.setFontSizeMultiplier(Slot::Heading4, 1.15);
t.setFontSizeMultiplier(Slot::Heading5, 1.05);
t.setFontSizeMultiplier(Slot::Heading6, 1.0);
t.setFontSizeMultiplier(Slot::Math,     1.0);
t.setFontSizeMultiplier(Slot::Quote,    1.0);
```

Existing H1/H2/H3 multipliers stand. `defaultDark()` derives from
`defaultLight()` so it inherits these automatically.

### 2.5 Body / Heading / Monospace base sizes

`defaultLight()` currently sets all three roles to 11pt. **Bump to
match prior visible behaviour** so the wire-up is non-disruptive:

```cpp
t.setFont(FontRole::Body,      QFont("sans-serif", 10.5));  // ≈14 px
t.setFont(FontRole::Monospace, QFont("monospace",  9.75));  // ≈13 px
t.setFont(FontRole::Heading,   QFont("sans-serif", 10.5));  // ≈14 px (H6 baseline)
```

10.5pt × 96/72 = 14px. 9.75pt × 96/72 = 13px. The H1/H2/H3 multipliers
on top of 10.5pt (1.8/1.5/1.3) yield 25.2/21/18.2px — slightly smaller
than today's 28/24/20. Acceptable: today's literals were chosen ad-hoc;
matching the multiplier table is more internally consistent.

**Document this delta** in `docs/handoff/` after E2.6 ships so future
dogfood feedback can compare against expected values.

### 2.6 New tests (`libs/markoff-core/tests/`)

- `tst_theme_pixelSizeFor` — slot→role map produces expected values
  for `defaultLight()`; multiplier=0 falls back to 1.0; pointSize=0 falls
  back to 11pt; HiDPI scaling stays Qt's job (assert raw 96-dpi values).
- `tst_theme_familyFor` — slot→role map returns the correct family for
  Body/Heading/Monospace slots.
- Extend `tst_theme_defaults` (if it exists; otherwise add) with the
  new H4/H5/H6/Math/Quote multipliers.

## 3. `LiveListModelBinding` additions (`libs/markoff-live`)

### 3.1 `fontScale` Q_PROPERTY

```cpp
class LiveListModelBinding : public QObject {
    Q_OBJECT
    // ... existing properties ...
    Q_PROPERTY(qreal fontScale     READ fontScale WRITE setFontScale NOTIFY fontScaleChanged)
    Q_PROPERTY(qreal fontScaleStep READ fontScaleStep CONSTANT)  // for QML wheel handler (§5.6)
public:
    qreal fontScale()     const noexcept;
    qreal fontScaleStep() const noexcept { return kFontScaleStep; }
    void  setFontScale(qreal s);  // clamps to [kMinFontScale, kMaxFontScale]
Q_SIGNALS:
    void fontScaleChanged();
};
```

### 3.2 Bounds + step constants

Defined in the header alongside the property:

```cpp
inline constexpr qreal kMinFontScale  = 0.5;
inline constexpr qreal kMaxFontScale  = 3.0;
inline constexpr qreal kFontScaleStep = 1.10;  // multiplicative
inline constexpr qreal kDefaultFontScale = 1.0;
```

`setFontScale` clamps writes silently. Out-of-range writes are not an
error; they snap to the bound.

### 3.3 `setFontScale` semantics

- Clamps to `[kMinFontScale, kMaxFontScale]`.
- Emits `fontScaleChanged` only when the **clamped** value differs from
  the current value (avoids re-render when user keeps hammering Ctrl+=
  past the upper bound).

### 3.4 InlineHighlighter font-scale propagation

Code-spans rendered by `InlineHighlighter::formatFor` use
`theme->font(Monospace).pointSizeF()` directly. **Without changes, an
inline `` `code` `` span inside a paragraph would not scale with the
document zoom.** Fix by threading fontScale through:

- `InlineHighlighter::setFontScale(qreal)` — setter + member; calls
  `rehighlight()` on change.
- `InlineHighlighterAttached::fontScale` — new `Q_PROPERTY(qreal
  fontScale READ WRITE NOTIFY)`; pushes through to the highlighter.
- Each delegate adds one binding line:

  ```qml
  InlineHighlighterAttached {
      // ... existing properties ...
      fontScale: root.liveBinding ? root.liveBinding.fontScale : 1.0
  }
  ```

- `InlineHighlighter::formatFor` for `span.code`:
  ```cpp
  fmt.setFontPointSize((mono.pointSizeF() > 0 ? mono.pointSizeF() : 11.0) * m_fontScale);
  ```

## 4. Delegate-side wiring (`libs/markoff-live/qml/delegates/`)

Each delegate replaces hardcoded `font.*` with a 4-line block:

```qml
readonly property var theme: root.liveBinding ? root.liveBinding.theme : null
readonly property real fontScale: root.liveBinding ? root.liveBinding.fontScale : 1.0
readonly property int  baseSlot: <chosen slot for this delegate>

font.pixelSize: theme ? theme.pixelSizeFor(baseSlot) * fontScale : 14 * fontScale
font.family:    theme ? theme.familyFor(baseSlot) : ""
font.bold:      theme ? theme.isBold(baseSlot) : false
font.italic:    theme ? theme.isItalic(baseSlot) : false
```

### 4.1 Per-delegate slot assignments

| Delegate (and sub-element) | Slot | Notes |
|---|---|---|
| `ParagraphDelegate` (TextEdit) | `TextDefault` | mult=1.0 → 14 px |
| `HeadingDelegate` (TextEdit) | `Heading1`…`Heading6` | switch on `model.headingLevel`; remove the literal pixel switch entirely |
| `BlockquoteDelegate` (TextEdit) | `Quote` | mult=1.0; italic comes from `theme.isItalic(Quote)` — set in `defaultLight()` per §2.4 (NEW) |
| `CodeBlockDelegate` (TextEdit) | `CodeBlock` | mult=1.0 → 13 px monospace |
| `ListItemDelegate` body (TextEdit) | `TextDefault` | matches paragraph |
| `ListItemDelegate` marker (Text) | `TextDefault` family **overridden to monospace** — uses `theme.font(Monospace).family()` directly, size = `theme.pixelSizeFor(TextDefault) * fontScale` |
| `MathDelegate` (both spots) | `Math` | mult=1.0 → 13 px (Math role mapped to Monospace) |
| `ImageDelegate` caption | `TextDefault` | size = `pixelSizeFor(TextDefault) * 0.85 * fontScale`, italic always-true (caption affordance) |
| `CodeBlockDelegate` language tag | `TextDefault` | size = `pixelSizeFor(TextDefault) * 0.8 * fontScale` |
| `RemoteCursorOverlay` label | `TextDefault` | size = `pixelSizeFor(TextDefault) * 0.65 * fontScale` |

Auxiliary text uses literal coefficients (0.85 / 0.8 / 0.65) at the
delegate site rather than introducing dedicated slots — these are
chrome, not content kinds, and don't warrant new `Theme::Slot`
identifiers.

**Required addition to §2.4:** `defaultLight()` also sets
`t.setItalic(Slot::Quote, true)` so blockquote italics survive theme
wire-up.

### 4.2 Removing the heading switch

`HeadingDelegate.qml`'s switch block is replaced wholesale:

```qml
readonly property int slotForLevel: {
    switch (model.headingLevel) {
        case 1: return Theme.Heading1
        case 2: return Theme.Heading2
        case 3: return Theme.Heading3
        case 4: return Theme.Heading4
        case 5: return Theme.Heading5
        default: return Theme.Heading6
    }
}
font.pixelSize: theme ? theme.pixelSizeFor(slotForLevel) * fontScale : 14 * fontScale
font.bold:      theme ? theme.isBold(slotForLevel) : (model.headingLevel <= 3)
```

The `font.bold: model.headingLevel <= 3` rule moves into Theme:
`defaultLight()` adds `setBold(Heading3, true)` so H1/H2/H3 are bold by
default, matching today's behaviour. (H1/H2 already set; H3 is the
delta.)

### 4.3 The `lineH` references

Five delegates use `const lineH = edit.font.pixelSize` inside
`focusEditAt` for cursor positioning. **No change needed** — they already
read the bound `font.pixelSize`, which now flows from theme + fontScale.
Verified by inspection.

## 5. `LiveActionController` additions

### 5.1 New QActions

Five new actions added to `setupActions()`:

```cpp
m_zoomIn      = new QAction(tr("Zoom In"),       this);
m_zoomOut     = new QAction(tr("Zoom Out"),      this);
m_zoomReset   = new QAction(tr("Reset Zoom"),    this);
m_toggleDark  = new QAction(tr("Toggle Dark Mode"), this);

m_zoomIn   ->setShortcut(QKeySequence(Qt::CTRL | Qt::Key_Equal));
m_zoomOut  ->setShortcut(QKeySequence(Qt::CTRL | Qt::Key_Minus));
m_zoomReset->setShortcut(QKeySequence(Qt::CTRL | Qt::Key_0));
m_toggleDark->setShortcut(QKeySequence(Qt::CTRL | Qt::SHIFT | Qt::Key_D));
```

`Ctrl+=` is the engineering name for the `Ctrl+Plus` chord that the OS
key map produces from `Shift+=`. Qt's `Qt::Key_Equal` covers the
unshifted variant; the `Ctrl+Shift+=` chord is added as a secondary
shortcut so both key topologies work:

```cpp
m_zoomIn->setShortcuts({
    QKeySequence(Qt::CTRL | Qt::Key_Equal),
    QKeySequence(Qt::CTRL | Qt::Key_Plus),
    QKeySequence(Qt::CTRL | Qt::SHIFT | Qt::Key_Equal),
});
```

### 5.2 Triggers

```cpp
connect(m_zoomIn,    &QAction::triggered, this, [this]{
    if (m_binding) m_binding->setFontScale(m_binding->fontScale() * kFontScaleStep);
});
connect(m_zoomOut,   &QAction::triggered, this, [this]{
    if (m_binding) m_binding->setFontScale(m_binding->fontScale() / kFontScaleStep);
});
connect(m_zoomReset, &QAction::triggered, this, [this]{
    if (m_binding) m_binding->setFontScale(kDefaultFontScale);
});
connect(m_toggleDark,&QAction::triggered, this, [this]{
    m_isDark = !m_isDark;
    Q_EMIT themeToggleRequested(m_isDark);
});
```

### 5.3 New signal + state

```cpp
Q_SIGNALS:
    void themeToggleRequested(bool dark);
private:
    bool m_isDark = false;  // tracks last-emitted state; flipped on each trigger
```

The host app connects this signal and applies a theme. `setTheme` takes
`const Theme*`, so the host must hold the value in a local before
passing the address — `Theme::defaultDark()` returns by value:

```cpp
connect(actions, &LiveActionController::themeToggleRequested,
        this, [binding](bool dark) {
    Markoff::Theme t = dark ? Markoff::Theme::defaultDark()
                            : Markoff::Theme::defaultLight();
    binding->setTheme(&t);  // setTheme copies; t can go out of scope after
});
```

### 5.4 `setBinding(LiveListModelBinding*)` accessor

`LiveActionController` already holds pointers to `MarkoffDocument` /
`LiveSelectionView` / `LiveClipboardController` / `LiveFormatController`,
each wired by external setup code (the test app, future hosts). Add
`setBinding(LiveListModelBinding *)` following the same pattern. The
test app calls `actions->setBinding(binding)` at the same site where it
calls the existing setters.

### 5.5 New Q_PROPERTY exposure (existing actions group)

Expose the four new `QAction *` getters as `Q_PROPERTY` for QML. Pattern
matches existing action exposure (`actionCut`, `actionCopy`, etc.).

### 5.6 Wheel zoom

`LiveView.qml` adds a Qt 6 `WheelHandler` at the ListView level (not a
`MouseArea` — `WheelHandler` composes correctly with the existing
ListView wheel-scroll handling and respects `acceptedModifiers`):

```qml
WheelHandler {
    target: null  // don't consume; we only react when Ctrl is held
    acceptedModifiers: Qt.ControlModifier
    onWheel: (event) => {
        const steps = event.angleDelta.y / 120.0
        if (steps === 0) return
        const cur = root.binding.fontScale
        const factor = Math.pow(root.binding.fontScaleStep, steps)
        root.binding.fontScale = cur * factor
        event.accepted = true
    }
}
```

`fontScaleStep` is exposed as a `Q_PROPERTY(qreal fontScaleStep CONSTANT)`
on `LiveListModelBinding` returning `kFontScaleStep`. Single source of
truth; no QML-side magic number.

## 7. Subtractability (per E-arc framing §5)

A view that does not need zoom or theming can avoid the runtime cost:

- **Skip zoom**: do not bind `Ctrl+= / -` / wheel handlers. `fontScale`
  defaults to 1.0; `pixelSizeFor(slot) * 1.0` is the same as
  `pixelSizeFor(slot)`. No QAction registration, no binding
  re-evaluation cost beyond the property read.
- **Skip theming**: do not call `setTheme()`. `defaultLight()` is the
  baseline; the delegate's `font.*` bindings re-evaluate exactly once
  at construction.
- **Skip inline scaling**: do not bind `InlineHighlighterAttached`'s
  `fontScale` — it defaults to 1.0; code-span size unchanged.

E2.6 introduces no required runtime cost for non-consumers.

## 8. Out of scope (deferred)

| Item | Why deferred |
|---|---|
| `QSettings` persistence | D4 (session-only). Add when a host needs it. |
| Custom theme loading via JSON file picker | UI surface; minimal `Theme::fromJson` already exists at the API layer. Host responsibility. |
| Per-document zoom (frontmatter) | Pollutes documents with view config; rejected in brainstorm. |
| Pinch-to-zoom on touch | Not currently a Markoff target platform. |
| System dark-mode auto-follow | Host-app concern; library just emits the toggle signal. |
| Theme editor / colour picker UI | Out of E-arc scope. |
| Per-block font overrides (e.g., per-language code-block fonts) | E-arc rendering question; not theming. |

## 10. Acceptance criteria (definition of done)

1. Every text element in §4.1 visibly draws its font from theme + fontScale.
2. `Ctrl+=` / `Ctrl+-` / `Ctrl+0` / `Ctrl+wheel` resize all text uniformly.
3. `Ctrl+Shift+D` (when wired by the host) toggles between
   `defaultLight()` and `defaultDark()`; colours and inline-highlight
   formats update in-place.
4. The 186 tests passing at the start of E2.6 remain green; new tests
   from §6.1 added and passing.
5. An interactive dogfood pass on a representative document signs off
   on the visual transition (size deltas from §2.5 acknowledged).
6. Tag `v0.7.0-e2.6` after dogfood.
